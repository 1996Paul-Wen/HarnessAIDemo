The root exposes a single CLI entry point (`run.py` → `harness.cli:main`, also installed as the `harness-demo` console script) that dispatches subcommands (chat, agent, multi-agent, mcp, skills, session) to demo scripts under `demos/`. The `setup.sh` script provisions a Python 3.11 virtual environment, installs dependencies from `requirements.txt`, and installs the package in editable mode so both the `harness` package and the `demos` scripts share one runtime. Environment variables such as `HARNESS_LLM_BACKEND` and `HARNESS_MODEL_NAME` control whether demos use a mock or real transformers-based LLM backend, which is the common wiring surface between the harness core and every demo.
