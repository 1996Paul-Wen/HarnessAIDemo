The module is organized into three layers around a single abstract contract. `base.py` defines the `BaseTool` ABC and the `ToolResult` dataclass, which every tool must implement (`name`, `description`, `parameters`, `execute(**kwargs) -> ToolResult`) plus helper methods `to_description()` and `to_schema()` for prompt/schema generation. `registry.py` implements `ToolRegistry`, a central catalog that stores tools by name, exposes `register`, `get`, `list_tools`, `execute(name, arguments)` (with unified error handling returning `ToolResult(success=False, ...)`), and `get_tools_description()` to render all tool descriptions for the system prompt. `builtin.py` ships three concrete tools — `CalculatorTool`, `DateTimeTool`, `FileOpsTool` — each subclassing `BaseTool` and returning `ToolResult` instances; a `register_default_tools(registry)` helper populates a registry with them. The package `__init__.py` re-exports the public surface (`BaseTool`, `ToolResult`, `ToolRegistry`, the built-in tools, and `register_default_tools`). Dependency direction is one-way: `builtin` and `registry` depend on `base`; nothing depends on `builtin` from within the package except the registration helper.
